# xr-poster-practice

学会のポスター発表を一人で練習するための WebXR 試作。
ブラウザだけで動き、ヘッドセットがあればそのまま被って練習できる。

公開先: https://ryutoyoda.github.io/xr-poster-practice/

## 何のための試作か

ポスター発表で難しいのは、話す内容ではなく**場の制御**のほう。
聴衆は発表の途中で勝手に来て勝手に帰るので、

- 新しく来た人に気づいて話を戻せるか
- 熱心な一人と話し込んで、他の人を置き去りにしていないか
- ポスターばかり見て、人の方を見られているか

といったことが問われる。これらは原稿を読み上げる練習では一切鍛えられず、
本番で失敗して初めて気づく。しかも本番は年に数回しか来ない。

鏡の前の練習や録画の見返しでは、そもそも**聴衆がいない**ので再現できない。
聴衆の出入りと立ち位置という空間的な条件そのものが練習対象なので、
2Dの画面では置き換えられない。

## 練習の流れ

1. ポスターの前に立つ（正面が聴衆、左手がポスター）
2. 開始すると、聴衆が時刻表どおりに来たり帰ったりする
3. 2〜3分話す。どこを向いていたかが記録される
4. 終わると記録が返り、次回の難度が自動で決まる

難度は聴衆の人数と入れ替わりの激しさで3段階。
前回の結果が目安に届いた観点の数だけ上がる。

## 返ってくるもの

| 観点 | 目安 |
|---|---|
| 新しく来た人に気づくまでの平均秒数 | 10秒以内、かつ気づかれないまま帰った人が0人 |
| 最も長く見た一人が占める割合 | 40%以下 |
| ポスターを見ていた割合 | 35%以下 |

加えて、発表中に一度も使わなかったポスターのパネルを出す。

記録は xAPI 風の statement（`arrived` / `noticed` / `departed`）として組み立て、
ブラウザの localStorage に置いている。LRSには送っていない。
結果画面の「記録（xAPI風）を見る」で中身を確認できる。

## ファイル

| パス | 内容 |
|---|---|
| `index.html` | 会場・ポスター・UI。ポスターのパネルはここで生成する |
| `js/scenario.js` | 立ち位置、パネル、難度ごとの時刻表、目安、次回難度の決め方 |
| `js/session.js` | セッション本体。聴衆の出し入れ、視線の記録、xAPI風statementの生成 |
| `js/feedback.js` | 終了後の集計・提示・履歴の保存 |
| `js/jp-label.js` | 日本語ラベルを3D空間に出すコンポーネント |

A-Frame 1.6.0 を CDN から読むだけで、ビルド工程も依存パッケージも無い。

## 作りの要点

- **視線はアイトラッキングではない。** カメラから前方に raycaster を飛ばして、
  当たった対象を見ているとみなしている。つまり「目を向けた先」ではなく
  「顔を向けた先」。安価なHMDにアイトラッキングが無いことを前提にした割り切り
- **アバターの身長は約1.7mにしてある。** ここを低くすると、発表者（目線1.6m）が
  水平に見ているつもりでも視線が頭の上を素通りして、何も記録されなくなる
- **帰った人も集計に残す。** 居る人だけで平均を取ると、
  「気づかれないまま帰った人」という最も見たい失敗が消えてしまう
- **日本語は `<a-text>` では出ない。** A-Frame標準のMSDFフォント（Roboto）に
  日本語グリフが無いため、canvasに描いてテクスチャとして貼っている（`js/jp-label.js`）
- **文字数が変わったらテクスチャを作り直す。** canvasを縮めて `needsUpdate` を立てても、
  GPU側の確保は前のサイズのまま。古い広い絵が新しい狭い板に押し込まれて、
  「終了」の裏に前の「残り 0:01 聴衆 3人」が潰れて残る
- **到着した人の足元が光る。** 現実にはこんな手がかりは無い。
  気づく練習の足場として最初だけ出し、一度見たら消える

## 動かし方（ローカル）

```bash
python3 -m http.server 8913
# http://localhost:8913/
```

`?speed=20` を付けると時間が20倍で進む。動作確認用。
